# State of the research programme

**Snapshot as of 2026-08-25.** Two branches, both closed. Track A is **paused** — see D21. This is a
handoff document, not a hypothesis. Every number cites the run it came from.

---

## The position in one paragraph

Two independent research branches ran to completion against a controlled synthetic benchmark. Neither
produced a novel algorithm; both produced a closed mechanism and a transferable methodological
lesson. Track A is now paused — **not** because the questions ran out, but because the repository has
no remaining source of observations it does not itself generate. Resuming requires real pilot data.

## What we know — AI engine branch

| Finding | Evidence |
|---|---|
| **The deployed model was capacity-uncontrolled.** Its exact config ranked *last* in E6's grid: val Brier 0.15760 vs 0.12858 for `min_samples_leaf=50` | E6 |
| **Under valid selection, a regularized logistic is Brier-indistinguishable from the exact oracle** — +0.00031, CI [−0.00241, +0.00301] | E6 |
| …**but not per-state indistinguishable** — oracle MAE 0.01856 against a 0.01 threshold. Outcome **A′**, predicted in advance | E6 |
| **The residual lives in the endgame**, and was a missing functional form. An exact finite-horizon estimator with **zero learned parameters** cuts competitive-state oracle MAE 0.18475 → **0.00681** | AE-1 |
| **The dominant missing structure was wicket dynamics, not discreteness.** Exact-but-wicket-free is *worse* than Gaussian-and-wicket-free (0.04122 vs 0.02767) — two errors were cancelling | AE-1, A5₀ ablation |
| **A correct feature can be inert where it matters.** The margin term added to the learned basis bought 1.7%; the same quantity in closed form bought 85% | AE-1 → D19 mode 7 |

Production defects found and fixed en route (Part 1): a training/serving feature skew moving
predictions by a mean of 0.126, first-innings serving of a chase-only model, 792 duplicated training
rows, and 200 MB of models trained on uniform random labels.

## Measurable vs not measurable, at CricRoots' operating point

**Measurable**: aggregate predictive performance; per-player scalar effects; ground-truth recovery
via oracles (Track A only); whether a mechanism is active, converged and correctly implemented.

**Not measurable**: per-entity utility of a richer representation (reliability −0.11); anything
requiring real-world validation (Track B blocked); **anything requiring a target the system does not
itself generate** (D21).

---

## Why Track A is paused

A component supports a research question only if it has an observable target **not generated by the
thing being evaluated**, plus an oracle or enough data. After AE-1, nothing in the repository
qualifies. The AI engine did only because it had an observable outcome *and* an exact oracle — the
latter available solely because `matchSimulator.js` is i.i.d.

**What unpauses it**: two assets that exist structurally but are empty, and that pilot adoption
creates rather than analysis —

1. **Human Man-of-the-Match overrides** — the only human judgment recorded against an algorithmic one
2. **User match predictions** — human forecast against outcome, independent of any model

Together they support a question the simulator cannot pose: *when do humans and the model disagree,
who is right, and can a system learn when to defer?*

**Blocking prerequisite**: `Match.manOfTheMatch` stores only a Player ref, with no record of whether
a human or the algorithm chose it. Every override would be captured as indistinguishable from an
algorithmic pick, and it is unbackfillable. See
`documentation/evidence-provenance-backlog.md` §1b — this must land before the first real match.

## What this programme produced

Not an algorithm. An environment that reliably detects when a question cannot be answered with the
evidence available, and a discipline for closing mechanisms without closing questions.

Across both branches: **eleven experiments, seven hypotheses refuted or unsupported, three of my own
conclusions retracted mid-arc**, two designs amended *before* running because they failed their own
validity gates, and one experiment (AE-1) that stopped a synthetic world from being built for a
reason that turned out to be wrong.

The retractions and the failed gates are in the git history rather than tidied away. If an algorithm
eventually emerges, that history is what will make it credible. If none does, this is still the
contribution.
